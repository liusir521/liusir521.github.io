大语言模型原理详解：从 Transformer 到 Scaling Law

深入浅出介绍大语言模型的核心原理，包括 Transformer 架构、注意力机制、训练流程、Scaling Law 和涌现能力

May 02, 2026
阅读时长: 5 分钟

引言

2022年11月，ChatGPT 横空出世，两个月内月活破亿。此后，GPT-4、Claude、Gemini、Llama、DeepSeek 等大语言模型（Large Language Model, LLM）层出不穷，深刻改变了人机交互范式。

这些模型的背后是一套精妙的理论体系：从 Transformer 架构到注意力机制，从预训练到对齐，从 Scaling Law 到涌现能力。本文尝试从头梳理这些核心原理，帮助读者建立对 LLM 的系统性认知。

读完本文你会理解：

  • Transformer 为什么能取代 RNN/LSTM
  • Self-Attention 到底在"注意"什么
  • 一个 token 是如何一步步生成的
  • 为什么模型越大能力越强
  • RLHF 如何让模型"听话"

语言模型的前世今生

统计语言模型时代

语言模型的核心问题很简单：给定前文，预测下一个词的概率。

$$ P(w_t \mid w_1, w_2, \dots, w_{t-1}) $$

最朴素的做法是 N-gram 模型——假设当前词只与前 N-1 个词相关。N=2（Bigram）时，“我/爱/吃” 后面接 “苹果” 的概率就是 count(“吃苹果”) / count(“吃”) 的统计频率。

N-gram 的问题很明显：稀疏性。自然语言中大部分词组从未在训练集中出现，概率为 0；增大 N 虽然能捕捉更长依赖，但参数呈指数爆炸。

神经网络语言模型

2003年 Bengio 提出用神经网络做语言建模，将每个词映射为稠密向量（词嵌入），再用全连接网络预测下一个词。这解决了稀疏性问题，但依赖固定窗口，仍然看不了长距离。

RNN/LSTM 时代

循环神经网络（RNN）天然适合序列建模，每步输出状态传递给下一步，理论上可以捕捉任意长度的依赖。LSTM 引入门控机制缓解了梯度消失。

问题是：无法并行计算——第 t 步依赖第 t-1 步的状态，训练慢得令人绝望。长序列的梯度传播仍然不稳定。

Transformer 革命

2017年 Google 发表《Attention Is All You Need》，提出纯 Attention 架构取代循环结构。核心洞见是：序列中任意两个位置的交互距离是 O(1)，而且可以完全并行计算。Transformer 成为 LLM 时代所有主流模型的基础架构。

Transformer 架构全景

Transformer 原始设计是 Encoder-Decoder 结构，但 LLM 大多只使用 Decoder（GPT 系）或 Encoder（BERT 系）。下面以 GPT 式 Decoder-Only 架构展开。

从宏观看，模型就是一个巨大的函数：

1

输入 tokens → [Embedding] → [N 层 Transformer Block] → [LM Head] → 概率分布

每个 Transformer Block 包含两个核心子层：

1

x → [Multi-Head Self-Attention] → [Add & Norm] → [FFN] → [Add & Norm] → 输出

训练好的模型权重里，参数分布在四个矩阵族中：

  • Q/K/V/O 矩阵（Attention 部分）：控制"从哪读信息"
  • FFN 矩阵（前馈部分）：存储"知识"
  • Embedding 矩阵：将 token 映射为向量
  • LM Head 矩阵：将向量映射回词表概率

核心一：Self-Attention 自注意力机制

为什么需要注意力

读这句话：“小明把苹果给了小红，因为她很__”。

空白处该填什么？理解 “她” 指代 “小红” 而非 “小明”、理解 “给苹果” 这个动作的后续，都需要综合多个位置的信息。卷积和 RNN 处理这种依赖能力有限。

Self-Attention 的基本思想是：让序列中每个位置都去"看"序列中的所有位置，并根据相关性加权聚合信息。

Query, Key, Value

这可能是注意力机制中最令人困惑的设计。一个直觉类比——数据库查询：

概念 数据库 Self-Attention
Query 你的 SQL 查询 当前 token 的"需求"向量
Key 索引列 所有 token 的"标签"向量
Value 数据行 所有 token 的"内容"向量

当你查询 SELECT * WHERE name = '苹果'，数据库用查询条件（Query）去匹配索引（Key），找到匹配行后返回数据（Value）。

Self-Attention 的计算完全一致：

  1. 当前 token 产出一个 Query 向量（“我想要什么信息”）
  2. 所有 token 各产出一个 Key 向量（“我有什么信息”）和一个 Value 向量（“我的实际内容”）
  3. Query 与所有 Key 做点积求相似度 → 得到注意力权重
  4. 用权重对所有 Value 加权求和 → 得到当前 token 的上下文表示

写成公式：

$$ \text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V $$

一步一步拆解

假设序列长度 n=4，每个向量维度 d=512：

Step 1 — 线性投影

输入 X 的 shape 是 [4, 512]（4 个 token，每个 512 维）。用三个权重矩阵投影：

1
2
3

Q = X @ W_Q    # [4, 512] × [512, 64] = [4, 64]
K = X @ W_K    # [4, 512] × [512, 64] = [4, 64]
V = X @ W_V    # [4, 512] × [512, 64] = [4, 64]

Step 2 — 计算注意力分数

1

scores = Q @ K^T / sqrt(64)    # [4, 64] × [64, 4] = [4, 4]

得到 [4, 4] 的注意力矩阵，scores[i][j] 表示第 i 个 token 对第 j 个 token 的"关注程度"。

除以 sqrt(d_k) 是为了防止点积值过大，导致 softmax 梯度消失。为什么是 sqrt(d_k)？因为随机初始化时 Q 和 K 的每个维度期望为 0、方差为 1，点积的期望就是 0、方差就是 d_k。

Step 3 — Softmax 归一化 + Causal Mask

1

weights = softmax(scores, dim=-1)    # [4, 4]，每行和为 1

Decoder 模型还需要 Causal Mask（因果掩码） ——将 scores 矩阵的上三角置为 -inf，确保第 i 个 token 只能看到位置 0~i，不能偷看未来。放到 softmax 之前做：

1

scores[i][j] = -inf   (for j > i)   # 每个 token 只能看到自己及之前的 token

所以 Causal Mask 也常被称为 下三角掩码，因为它最终保留的是一个下三角矩阵——每个位置只能看到它前面（含自己）的内容。

Step 4 — 加权聚合

1

output = weights @ V    # [4, 4] × [4, 64] = [4, 64]

每个 token 的输出来自对所有（可见）token 的 Value 按注意力权重加权求和。

Multi-Head Attention

单头注意力只能捕捉一种关系模式。比如在 “小明把苹果给了小红，因为她很__” 中，需要同时关注指代关系（她→小红）和语义搭配（吃/喜欢+苹果）等不同维度。

多头注意力就是并行做多组独立的 Q/K/V 投影，每组叫做一个"头"（head）：

1
2
3
4
5
6
7

对每个 head_i:
    Q_i = X @ W_Q_i
    K_i = X @ W_K_i
    V_i = X @ W_V_i
    head_i = Attention(Q_i, K_i, V_i)

MultiHead = Concat(head_1, head_2, ..., head_h) @ W_O

每个头可以学到不同的注意力模式：有的头关注相邻词做语法建模，有的头关注远距离指代，有的头关注标点边界。实际的注意力模式远比"相邻"和"远距离"复杂，不同层、不同头的分工至今仍是可解释性研究的前沿课题。

以 Llama 3 70B 为例：d_model=8192，num_heads=64，每个头的 d_k=128。64 个不同的"视角"并行工作。

核心二：Feed-Forward Network 前馈网络

每个 Transformer Block 的 FFN 是一个两层的全连接网络：

$$ \text{FFN}(x) = \text{GeLU}(xW_1 + b_1)W_2 + b_2 $$

通常 hidden_dim 是 d_model 的 4 倍。比如 d_model=4096 的模型，FFN 中间层有 16384 维。

FFN 承担了知识存储的角色。研究表明，Transformer 中的事实性知识主要存储在 FFN 的参数中——可以把 FFN 理解为一种键值记忆：第一层做模式匹配（匹配输入模式），第二层输出对应的知识。

一个有意思的结论来自 Transformer Feed-Forward Layers Are Key-Value Memories（2020）这篇论文：FFN 的第一层（W1）的每一行可以看作一个 “Key”，负责检测某种输入模式；第二层（W2）的对应列则是这个 Key 对应的输出。这意味着 FFN 的参数本身就是一种可学习的关联存储。

一个对 GPT-2 的可解释性实验也印证了这一观点：如果用一个分类器去检测 “巴黎” “法国” “首都” 这几个概念在模型各层的激活情况，会发现 FFN 层的激活模式远比 Attention 层更集中——知识确实 “住” 在 FFN 里。

核心三：位置编码

Self-Attention 本身是置换不变的——打乱输入顺序，输出也跟着打乱但值不变。“我爱吃苹果"和"苹果爱吃我"对 Attention 来说，只是矩阵行排列的顺序不同。

因此需要显式注入位置信息。原始 Transformer 使用正弦位置编码：

$$ PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d_{model}}}\right) $$

$$ PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{model}}}\right) $$

不同频率的正弦波让模型能够学习相对位置关系（因为 sin(a+b) 可以展开为 sin(a)cos(b) + cos(a)sin(b)），且有良好的外推性——训练时见过 512 长度的序列，推理时遇到 1024 也勉强能处理。

现代 LLM 更多使用 RoPE（旋转位置编码） ，通过旋转矩阵将位置信息编码到 Q/K 向量中。RoPE 的优势是相对位置关系天然内嵌在向量内积中：两个位置 token 的注意力分数仅取决于它们的相对距离，不依赖绝对位置。Llama 系列、Gemma、Qwen 等主流模型均使用 RoPE。

核心四：Add & Norm

Transformer Block 中每一子层后都有残差连接 + 层归一化：

1

output = LayerNorm(x + Sublayer(x))

残差连接确保梯度可以无损地从顶层传导到底层，这是训练深网络的必要条件——100 层 Transformer 能训练，全靠残差提供的梯度"高速公路”。而 LayerNorm 稳定每一层的数值分布，防止数值发散。

Tokenization：模型如何"读"文本

模型不能直接理解原始文本，需要先分词（Tokenization）。现代 LLM 普遍使用 BPE（Byte Pair Encoding） 子词分词算法。

BPE 的核心思想是：从字符级别开始，迭代地将最高频的相邻符号对合并为一个新符号。

比如词表有限时，“apple” “apples” “application” 可能被拆成 “app” + “le” / “app” + “les” / “app” + “lication”。共用词根 “app” 大大压缩词表大小。

BPE 训练过程

  1. 初始化词表为所有单字符（256 个字节级别的基础符号）
  2. 统计训练语料中所有相邻符号对的频率
  3. 将最高频的符号对合并为一个新符号，加入词表
  4. 重复步骤 2-3，直到词表达目标大小（如 GPT-4 的 100K tokens）

Tokenization 的影响

分词方案直接决定模型的"世界观"。它带来几个关键约束：

尾部词问题。 BPE 对高频词完整保留（如 “the”），对低频词拆得很碎（如 “sesquipedalian” → [“ses”, “qui”, “ped”, “alian”]）。低频词占用更多 token，消耗更多算力。

多语言不平等。 同一句话，“Hello world” 占 2 tokens，“你好世界” 却可能占 6-8 tokens。非英语内容效率低下且成本更高——因为训练语料以英文为主，中文短语合并机会少得多。

“反转诅咒”。 模型知道"A 是 B"（A is B），但不会自动推出"B 是 A"（B is A）。这与训练数据的方向性有关——语料中很少同时出现两种表述。

训练流程：从原始文本到智能对话

LLM 的训练分为三个阶段。

第一阶段：预训练（Pre-training）

目标：让模型学会语言的统计规律和世界知识。

数据：数万亿 token 的文本——网页、书籍、代码、论文等。Common Crawl、The Pile、RefinedWeb 等是常用的预训练数据集。

任务：自回归语言建模——给定前面的 token，预测下一个 token。这个任务不需要标注数据，文本本身就是标签。

损失函数：交叉熵损失。对每个位置 t，模型输出词表大小的概率分布，损失就是真实 token 的负对数概率。

$$ \mathcal{L} = -\sum_{t=1}^{T} \log P(w_t \mid w_1, \dots, w_{t-1}) $$

预训练占整个训练成本的 99% 以上。GPT-3 训练成本约 460 万美元（2020 年价格），GPT-4 据说花了约 1 亿美元。

这个阶段产出的模型叫 Base Model，它能做文本补全但不会聊天——你问它"1+1=?"，它会回答"2+2=?"，因为它见过太多数学题序列，只是在续写。

第二阶段：监督微调（Supervised Fine-Tuning, SFT）

目标：让模型学会"对话格式"。

数据：人工标注的高质量对话——几千到几万条。格式为 {"prompt": "用户问题", "response": "理想回答"}。

SFT 本质上还是相同的语言建模任务，只是训练数据从"下一步续写"变成了"给定指令，生成回答"。数据量虽小但质量极高，通常几千到几万条即可让 Base Model 掌握对话能力。

SFT 之后模型就变成了我们熟悉的 Chat 模型。

第三阶段：RLHF（基于人类反馈的强化学习）

SFT 的局限在于：人类标注的"理想回答"只是人类偏好的一个点。模型需要理解的是——当有多种合理回答时，人类更偏好哪一种？长回答还是短回答？客观还是主观？详细还是简洁？

RLHF（Reinforcement Learning from Human Feedback） 解决的就是这个问题，分为三步：

Step 1 — 训练奖励模型（Reward Model, RM）。 让 SFT 模型对同一个 prompt 生成多个回答，人类标注员对这些回答进行排序（A > B > C > D）。用排序数据训练一个"打分器"——输入是 (prompt, response)，输出是一个标量分数（这个回答有多好）。

Step 2 — 用强化学习优化生成模型。 使用 PPO（Proximal Policy Optimization）算法：SFT 模型作为初始策略，对 prompt 生成回答，RM 给回答打分，奖励信号回传更新模型参数。关键技巧是加入 KL 散度惩罚项——防止模型为了刷分而偏离太远，生成莫名其妙的内容。

Step 3 — 迭代。 用更新后的模型生成新回答，收集新的人类偏好数据，重新训练 RM，再次 PPO。重复多次。

RLHF 让模型学到了人类难以用规则描述的偏好——什么是一个"好回答"。OpenAI 内部实验显示，1.3B 参数的 InstructGPT 在人类评估中胜过了 175B 的 GPT-3 Base Model——对齐比规模更能赢得人类认可。

RLHF 的替代方案

近两年业界也在探索 RLHF 的替代品：

DPO（Direct Preference Optimization） 直接从偏好数据优化模型，不需要显式训练奖励模型，数学上等价于 RLHF 但实现简单得多。Llama 3、Qwen 2 等模型都有使用 DPO 进行对齐。

RLAIF（RL from AI Feedback） 用更强的 AI（如 GPT-4）代替人类做偏好标注，降低人工成本。Anthropic 的 Constitutional AI 就是这一路线的代表——让 AI 根据一套"宪法"原则自我评估和改进。

Scaling Law：大就是好

2020年 OpenAI 发表论文提出 Scaling Law：模型的性能（以交叉熵损失衡量）与参数量 N、训练数据量 D 和计算量 C 三个因素之间遵循幂律关系。

通俗来说就是：算力每增加 10 倍，模型损失稳定下降一个可预测的量级，而且在相当大的范围内不存在平台期。

Chinchilla 定律

2022年 DeepMind 提出的 Chinchilla 定律给出了最优配比：每增加一个参数，应该增加约 20 个训练 token。

以 Llama 3 70B 为例，按 Chinchilla 定律需要约 1.4T 的训练 token。Meta 实际喂了约 15T——远超 Chinchilla 最优，属于"过度训练"（overtraining）策略，这是为了在推理成本（小模型更便宜）和训练成本之间做取舍。

但 Chinchilla 定律有重要的前置条件：它在给定 FLOPs 预算下寻找最优配比。如果你的约束不是 FLOPs 而是推理成本（如部署到手机），最优策略是用更多数据训练更小的模型——这也解释了 Llama 系列和各大开源模型为什么普遍"过度训练"。

Scaling Law 也不是万能的。数据质量在 2024-2025 年成为新瓶颈——互联网上的高质量文本正在被耗尽（所谓的"数据墙"）。合成数据可能是突破瓶颈的关键：用顶级模型生成训练数据来训练新模型，但这同时带来了模型同质化（model collapse）的风险。Phi-3、Llama 3 等模型在发布时都强调了数据质量的提高（而非仅仅是数据量的增加）带来了显著收益。

涌现能力：从量变到质变

LLM 一个令人着迷的现象是 涌现能力（Emergent Abilities）：某些能力在小模型中不存在，当参数超过某个阈值后突然出现。

典型的涌现能力——思维链（Chain-of-Thought, CoT）：

小模型做多步数学题：“小明有 5 个苹果，给了小红 2 个，又买了 3 个，现在有几个？” → 直接猜答案，错误率高。

大模型（>100B）：自动分步推理——“小明开始有 5 个 → 给了小红 2 个，剩下 3 个 → 又买了 3 个 → 共 6 个”，准确率大幅提升。

无需显式训练，仅是在 prompt 中示例分步推理（Few-shot CoT），甚至只说一句 “Let’s think step by step”（Zero-shot CoT），模型就能展现推理能力。

涌现的机制至今没有定论。一种主流解释是：复杂任务由多层简单的子任务组合而成，小模型每层"胜任度"不够，到达不了"组合爆发"的临界点。随着参数增长，每层子任务超过阈值，能力就突然出现。但这也只是假说，我们实际上对这种能力跃迁的理解还非常有限。

已知的涌现能力包括：算术推理、多语言翻译、代码生成、讽刺理解、心智理论等。

推理阶段：温度、Top-K 与 Top-P

模型输出的是一个概率分布（词表中每个 token 的概率），需要从中选择一个 token 作为输出。不同策略直接影响生成质量：

贪心解码（Greedy Decoding） 每次选概率最高的 token。确定性高，但容易陷入重复循环。永远生成相同输出。

温度采样（Temperature Sampling） 在 softmax 之前除以温度 T：

  • T→0：趋近贪心，趋于确定出最高概率 token
  • T=1：原始概率分布
  • T>1：概率分布更平滑，低概率 token 被"提权"，输出更多样但也更不可控

Top-K 采样 只从概率最高的 K 个 token 中采样，切断长尾噪声。比如 K=50 意味着只考虑 top-50，屏蔽剩下几万个 token。

Top-P 采样（Nucleus Sampling） 动态选择最小集合，使其累积概率 ≥ P。比 Top-K 更灵活：概率集中时选得少（精准），概率分散时选得多（多样）。

实际生产中通常是 Temperature + Top-P 组合使用。API 调用的 temperature 和 top_p 参数就是这么来的。

从原理到趋势

理解了上述原理，再看当下的技术趋势就会觉得顺理成章：

长上下文 挑战 Attention 的 O(n²) 复杂度。RoPE 外推 + FlashAttention 等工程优化，将上下文从 4K 推到 1M+ token 级别。FlashAttention 通过分块计算和 IO 优化，将原始 Attention 的内存瓶颈从 HBM 移到 SRAM，实现数倍加速。

MoE（混合专家） 将 FFN 层拆成 N 个"专家"，每个 token 只激活其中的 K 个（K«N）。DeepSeek-V3（671B 总参，37B 激活）、Mixtral 8x7B 都是 MoE 架构。用路由网络（一个轻量分类器）为每个 token 选择最合适的专家，让容量接近稠密大模型，推理成本接近稠密小模型。

多模态 将图像、音频也 token 化，用相同的 Transformer 统一处理。GPT-4V/GPT-4o 是闭源代表，LLaVA 是开源路线的典型。

推理时缩放（Inference-Time Scaling） 改变了过去仅在训练阶段堆算力的范式——让模型在推理时"思考更久"也能提升性能。典型例子是 OpenAI o1/o3 的推理模型，以及 DeepSeek-R1 所展示的纯强化学习激发推理能力的方法。

总结

大语言模型的原理体系可以总结为三个层次：

层次 核心组件 解决什么问题
架构层 Transformer, Self-Attention, FFN 如何高效地建模序列
训练层 Pre-training, SFT, RLHF/DPO 如何获得知识和遵循指令
规模层 Scaling Law, Emergence 做大能得到什么

理解这些不意味着我们能造出 GPT-5，但至少在使用和评估它们时，我们不再是面对一个"魔法黑箱"，而是一个可以分解、可以分析的工程系统。

大模型的下一幕正在展开。Agent 架构、代码生成与执行、多模态融合、端侧部署——每个方向都在重新定义我们与机器的关系。越是深入原理，就越能在浪潮中找到自己的立足点。
